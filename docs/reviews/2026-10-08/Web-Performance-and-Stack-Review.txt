TCGer web performance and stack follow-up — October 8, 2026

Current result
The local checkout now runs Next.js 16.4.0. The production frontend Docker image builds and runs successfully as user 1000. All 42 desktop/mobile Chromium workflows passed against that container, including the phone layout and search-failure regressions. The audit findings addressed below are implemented locally; checks were performed locally before committing, and production hosting was not deployed or inspected during this review.

Interface and repeated work fixed
- Ten unchanged authentication synchronizations previously published 10 auth-store and 160 module/preference-store updates. The same probe now publishes zero. Actual preference changes, session rotation and logout retain regression coverage.
- Initial authenticated dashboard load fell from four /health requests to one shared request. The updated-stack probe recorded no idle requests and no main text/child DOM changes over three seconds. This measures the dashboard, rather than every component in the app.
- Card Explorer, result cards and the dashboard subscribe to the auth fields they need. Individual-binder browsing skips unused all-binder aggregation. Demo Card Explorer reuses the live page UI. Query developer controls are restricted to development.
- Phone settings and Card Explorer result actions fit the 320-pixel viewport. Provider failures are distinguished from empty searches, and partial results retain an explicit warning. Scryfall requests identify the app and preserve upstream failures. Request logging redacts credentials.

Security audit result
Before this follow-up: 77 affected package entries, including 3 critical; production omission audit: 27, including 3 critical.
Prior stack update: 35 full affected entries and 7 production entries. These represented five underlying advisory IDs.
Current advisory follow-up: 11 full affected entries — 0 critical, 7 high, 4 moderate, 0 low.
Current npm audit --omit=dev: 3 affected entries — 0 critical, 0 high, 3 moderate, 0 low.
The targeted replacements are deepmerge-ts 8.0.2 for Prisma config, postcss-selector-parser 7.1.6 for Tailwind/PostCSS Nested, esbuild 0.28.2 for affected versions, and js-yaml 4.3.2 replacing NYC’s legacy YAML chain. npm 11.19.0 is pinned in local instructions, CI and application Docker recipes because older npm ignores workspace overrides and rejects the patched lockfile.
The remaining 11 entries trace to two unpatched advisories: braces in development/build/lint tooling and sprintf-js through TensorFlow’s legacy argparse dependency. No application path exposing their vulnerable functions was identified; actual tensor execution did not load argparse or sprintf. This lowers observed exposure without erasing the dependency finding. The rebuilt frontend image contains no braces, argparse or sprintf-js directories or dotenv files in its traced server filesystem. It runs as UID 1000 and measures 548,993,833 bytes.
The updated image passes all 42 desktop/mobile Chromium checks; health, authenticated existing session and Android association JSON return 200. All 604 unit checks, 94 JavaScript API/health checks and 39 Convex API checks pass. Frontend/backend/Convex builds, Prisma config/schema/client generation, NYC YAML loading/extends, pack-core checks and scanner runtime smoke checks pass. Frozen scoped npm ci and the full-install dry run pass with npm 11.19.0.
A clean audit is not claimed. Detailed paths, advisory IDs and follow-up options are recorded in TCGer-Dependency-Advisory-Review.docx and the repository’s docs/dependency-security-review-2026-10-08.md.
